ResourceAwareLean

ResourceAwareLean is a Lean 4 framework for implementing algorithms abstractly and reusing their complexity analyses across different cost models. Each model is defined by the costs it assigns to individual operations.

GitHub Examples Get Started

The Idea

An algorithm is written as a sequence of abstract operations. Its control flow does not depend on a particular data structure or cost formula. A semantic model decides what each operation does, while a cost model independently assigns a cost to that operation. The assigned cost may depend on the operation, its inputs, and the state before or after it runs.

algorithm→ operation semantics→ operation costs→ measured trace→ resource analysis→ complexity bound

A generic interpreter combines these choices and records the operations in execution order. The framework proves that changing only the cost model does not change the algorithm's result, final state, or sequence of operations. The recorded trace can then be evaluated under another set of operation costs without rewriting the algorithm or repeating its correctness proof.

Examples

1. Different cost models — Mergesort

Problem. A complexity analysis depends on what work the model counts. For mergesort, one model may count only key comparisons, while another also accounts for splitting and merging. Baking either choice into the implementation makes the algorithm difficult to reuse.

Our approach. Mergesort requests abstract comparison, split, merge, and base-case operations. Each cost model assigns costs to those operations independently, so the algorithm and its correctness proof are reused across different accounting choices.

2. Different data structures — BFS, DFS, and Dijkstra

Problem. The resource use of a graph algorithm depends on its representation. Neighbor lookup differs between adjacency lists and matrices, and Dijkstra also depends on the chosen priority queue. Hard-coding these data structures ties the algorithm and its proof to one implementation.

Our approach. BFS, DFS, and Dijkstra are written against abstract graph and priority-queue interfaces. BFS and DFS are analyzed with adjacency-list and adjacency-matrix models. The current Dijkstra complexity theorem uses an adjacency-list model and the verified named heap.

3. Randomized algorithms — Randomized quicksort

Problem. A randomized algorithm can follow many execution paths, each with its own result and resource use. A single deterministic counter cannot capture the branch probabilities and their costs.

Our approach. Randomized quicksort requests pivot choices as abstract operations. A probabilistic interpreter supplies those choices, and RandCostM keeps their results and costs together. The case study proves sorted-permutation correctness and expected-cost bounds for duplicate-free inputs without defining a second quicksort implementation for randomized execution.

Scope and limitations

  • Exact costs are costs in the selected source-level operation model, not Lean evaluator or compiled-code runtimes.
  • Executable BFS and DFS prove exact reachability. The BFS shortest-path tree and DFS ancestor results use separate certificate structures that the executable runs do not currently construct.
  • Dijkstra assumes every enumerated vertex is reachable and uses canonically nonnegative ordered additive weights. Its textbook O(m log n) corollary is for adjacency lists and n ≥ 2.
  • The MergeSort asymptotic theorem is stated for power-of-two input lengths.
  • Randomized Quicksort's expected- and worst-cost theorems use distinct keys. Its comparison and textbook models include only their explicitly documented source-level charges.

What's Included

ResourceAwareLean

ResourceAwareLean expresses algorithms as free programs and interprets their behavior and resource use through separate semantic and cost models. It also provides ordered traces, probabilistic cost semantics, and reusable interfaces for graphs and priority queues.

TextbookAlgorithms

Case studies from Kleinberg and Tardos's Algorithm Design: BFS and DFS (Chapter 3), Dijkstra (Chapter 4), Mergesort (Chapter 5), and Randomized quicksort (Chapter 13).

RandCostM

RandCostM models randomized computations as distributions over result-cost pairs. It describes the Lean implementation of probabilistic choice, branchwise cost accumulation, and expected-cost reasoning.

ThirdParty

A clearly marked local copy of the experimental graph API from CSLib PR #503, kept until it merges upstream.

Get Started

git clone https://github.com/scorpsj77/ResourceAwareLean.git
cd ResourceAwareLean
lake build ResourceAware TextbookAlgorithms ThirdParty Examples
# Algorithm examples
lake env lean Examples/Algorithms/BFS.lean
lake env lean Examples/Algorithms/DFS.lean
lake env lean Examples/Algorithms/Dijkstra.lean
lake env lean Examples/Algorithms/MergeSort.lean
lake env lean Examples/Algorithms/RandomizedQuicksort.lean
# Infrastructure examples
